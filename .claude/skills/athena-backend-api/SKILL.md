# Athena Assistent backend-contract

## Transport
- De backend-URL staat niet in de code: de gebruiker vult hem in op het koppelscherm; `index.html` bewaart hem in `localStorage.aa_api` en de koppelcode in `localStorage.aa_secret`.
- Eén helper: `run(fn, arg1, ...)` → `Promise` met `result`. Request: `POST <url>?app=1`, body `JSON.stringify({ fn, args, secret })`.
- Geen request-headers toevoegen: een `Content-Type: application/json` header triggert een CORS-preflight en Apps Script beantwoordt geen OPTIONS.
- Response: `{ ok: true, result }` of `{ ok: false, fout }`. Bij `fout === 'secret'` wist `run()` de koppelcode en toont het koppelscherm. `run()` toast zelf bij fouten; in `.catch` alleen de UI herstellen.
- Functienamen beginnen met `api` + hoofdletter; de dispatcher in `Code.gs` accepteert niets anders.

## Gebruikers (v2.0)
- `doPost` zet `GEBRUIKER` via `wieIs(secret)`: `SECRET` = beheerder, een code uit scripteigenschap `CODES` = accountmanager. Geen geldige code → `fout: 'secret'`.
- `ikNaam()` is de naam voor `door`/`eigenaar`; `alleenBeheerder()` bovenaan elke beheerfunctie; `vanMij(eigenaar)` filtert eigen werk.
- v4.0: `GEBRUIKER = { naam, email, team, rol }` met team `management|consultancy|accountmanagement|talent` en rol `medewerker|teamlead|management` (`profielVan`, `gebruikerVan`). `isBeheerder()` = management. Rechten via `RECHTEN`, `mag(onderdeel, actie, rij)`, `eis(...)`, `eisKoppeling(o)`, `zichtbaarFilter()`, `taakVanMijOfTeam()`, `zichtbareMensen()`; de app krijgt `ik.rechten` (`rechtenUit()`). Elke nieuwe `api*`-functie filtert bij lezen en controleert bij schrijven. Mail en agenda alleen via `mijnMailbox()`-gecontroleerde functies; nooit Gmail/Calendar van de eigenaar aan een andere gebruiker tonen. Bewerk-api's krijgen `_oud` en roepen binnen `metLock` `controleerConflict(tab, id, nieuw, _oud)` aan.
- v5.0: `RECHTEN.talenten` en `RECHTEN.beoordelingen` (talent alles; accountmanagement `eigen` = kandidaat in een zichtbaar project, via `talentenViaProject()`; consultancy geen). **Portaal:** `doPost` met `req.portaal` (het token) zet vóór `wieIs` `GEBRUIKER = EXTERN` (`team: 'extern'`, staat in geen enkele `RECHTEN`-rij, dus `niveau()` geeft overal `geen` en `isBeheerder()` is onwaar), accepteert alleen `PORTAAL_FUNCTIES` en telt een budget in `CacheService` (30 per token per uur, 600 totaal). `talentVanToken` eist een geldig, niet verlopen `portaalToken`. Voeg nooit een portaalfunctie toe die iets anders leest of schrijft dan de eigen rij van dat talent; geen HtmlService. In de app: `runPortaal(fn, …)` post `{fn, args, portaal}` naar de `api` uit de URL (alleen `script.google.com/macros/` of localhost), nooit in `localStorage.aa_api`.

## Server op Vercel + Supabase (v6.0)
- Dezelfde `Code.gs` draait in Node (`server/code.js`) met nagebootste diensten (`server/apps-script.js`, `server/google.js`); `POST /api` neemt `{fn, args, secret}` óf `{fn, args, token}` (Supabase-sessietoken van de Google-login). De body is JSON zonder `Content-Type` (de app stuurt nooit headers; de browser zet `text/plain`), dus de server parseert de ruwe body zelf (`bodyParser: false` in `api/index.js`). De app bewaart de config van `GET api/config` als `aa_server` en start daarmee meteen, ook offline; alleen een onbekend toestel wacht (max. 3 s) op `api/config` en toont zonder antwoord "Geen verbinding" in plaats van het koppelcodescherm. `server/handler.js` controleert het token en zet het e-mailadres als `SERVER_LOGIN`; `wieIs()` in Code.gs gebruikt dan `gebruikerVanEmail(email)` (eigenaar via eigenschap/omgeving `EIGENAAR_EMAIL`, anderen via `Gebruikers.email`, inactief = geen toegang). Code.gs mag niets aannemen over Sheets-eigenaardigheden: de "Sheet" is Postgres (tabel per tabblad, kolommen in snake_case; getallen uit `NUMERIEK` in `server/schema.js` komen als getal terug, al het andere als tekst, leeg als `''`).
- Scripteigenschappen komen uit de tabel `eigenschappen`, met voorrang voor omgevingsvariabelen `ATHENA_<NAAM>` (sleutels zoals `ANTHROPIC_API_KEY` staan alleen in Vercel; `ATHENA_DB`, `ATHENA_GOOGLE_NEP` en `ATHENA_LOG` zijn van de server zelf en geen eigenschap). `ScriptApp.getService().getUrl()` is `APP_API_URL`. Triggers zijn cron-aanroepen van `GET /api/cron/<naam>` met `Authorization: Bearer <CRON_SECRET>`; `getProjectTriggers()` meldt ze als aanwezig.
- v6.2 (go-live-review): een token telt alleen met `aud: 'authenticated'` en, als `SUPABASE_URL` bekend is, `iss: <SUPABASE_URL>/auth/v1`. Antwoorden buiten het `{ok, result|fout}`-patroon: HTTP 429 `{ok:false, fout}` na 20 mislukte inlogpogingen per IP per 10 minuten (ook voor een goede code vanaf dat IP; het portaal valt erbuiten), HTTP 503 `{ok:false, fout}` bij een databasestoring (de app toont `fout` via `leesAntwoord`), geen CORS-header tenzij `ATHENA_CORS_ORIGIN`. `GET /api/config` geeft ook `maxBestand` (3 MB op Vercel; de app gebruikt dat voor documentuploads, Apps Script houdt 8 MB). De lock van `metLock` komt op de server pas na `flush()` vrij en een tweede volledige lezing van een ongewijzigd tabblad (`vergeet()` + `lees()`) laadt opnieuw uit Postgres, zodat `controleerConflict` een ander verzoek ziet. Nieuwe adaptermethoden: voeg ze toe en draai `node server/dekking.js` en `node server/vergelijk.js`.
- Een nieuwe Apps Script-methode in Code.gs heeft een stub nodig in `demo/demo-backend.js` én in `server/apps-script.js` of `server/google.js`; anders faalt `node server/test/server_test.js`. Een nieuwe kolom in `TABELLEN` komt op de server vanzelf (`zorgSchema`), maar genereer `supabase/migrations/0001_init.sql` opnieuw.
- `apiExportAlles(tabel, vanaf, aantal)` (management) is de bron van `server/migratie.js`; `'eigenschappen'` geeft de scripteigenschappen zonder `ANTHROPIC_API_KEY` en `CAPSULE_TOKEN`.
